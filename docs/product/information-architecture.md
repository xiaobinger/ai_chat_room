# 信息架构

## 1. 全局导航
- **聊天室**：默认入口，展示最近使用与进行中的房间。
- **角色工坊**：浏览内置角色，创建和测试自定义角色。
- **设置**：模型策略、预算、隐私和数据保留。

## 2. 页面地图
### 2.1 大厅 `/rooms`
展示房间卡片、状态、参与角色、当前主题和最近活动。主要操作为“创建聊天室”“继续讨论”“归档”。空态引导用户创建第一个房间。

### 2.2 创建房间向导 `/rooms/new`
五步：
1. 基础信息：名称、简介、可见性；
2. 讨论模式：主题讨论或自由聊天；
3. 添加角色：选择内置角色或进入角色工坊；
4. 管理规则：选择 AI 管理员、处罚阶梯和预算；
5. 启动确认：预览角色、主题、规则和预计上限。

支持保存草稿、上一步和退出后恢复。

### 2.3 聊天室 `/rooms/:roomId`
桌面端三栏：
- 左栏：房间导航、房间列表、创建入口；
- 中栏：主题进度、消息流、输入区、讨论控制台；
- 右栏：角色状态、管理员规则摘要、预算与轮次。

移动端改为单栏消息舞台，房间列表和角色/规则通过抽屉访问，讨论控制固定在底部但不得遮挡输入区。

### 2.4 角色工坊 `/roles`
角色库、筛选、角色详情和新建入口。角色编辑器 `/roles/:roleId/edit` 包含身份、性格、立场、表达风格、目标、知识边界、禁区与测试对话。

### 2.5 AI 管理员配置 `/rooms/:roomId/moderation`
展示规则模板、自定义规则、判断阈值、处罚阶梯、例外名单、动作预览和历史治理日志。高影响动作必须显式提示房主具有撤销权。

### 2.6 讨论复盘 `/rooms/:roomId/runs/:runId/review`
展示结论摘要、观点阵营、关键争论时间线、共识、未解决分歧、治理事件和继续讨论建议。所有摘要项提供“查看原消息”。

### 2.7 设置 `/settings`
包含模型与性能策略、默认预算、隐私、数据保留和危险操作。首版不展示供应商级高级路由。

## 3. 核心导航关系
- 大厅 → 创建向导 → 聊天室。
- 创建向导 → 角色工坊 → 返回向导并保留草稿。
- 聊天室 → 管理员配置 → 返回同一房间。
- 聊天室终止或完成 → 讨论复盘 → 以旧主题继续或创建新 Run。
- 任意页面 → 设置；返回时保留原页面上下文。

## 4. 聊天室信息优先级
1. 当前 Run 状态及紧急控制；
2. 当前主题与剩余轮次/预算；
3. 消息与引用关系；
4. 正在思考、发言、禁言或错误的角色；
5. 治理事件和撤销入口；
6. 次要配置和历史详情。

## 5. 全局状态
每个主要页面需要具备：首次空态、数据加载、操作进行中、成功反馈、可恢复错误、权限不足和网络断开状态。聊天室额外需要流式输出、暂停、角色失败、预算耗尽、管理员动作和重连补偿状态。

## 6. 响应式原则
- 1440 像素：完整三栏，中央消息区优先伸缩。
- 1024 像素：压缩左栏，右栏改为可收起面板。
- 390 像素：单栏，顶部显示主题和状态，底部固定控制，角色与规则使用抽屉。
- 所有尺寸禁止横向页面滚动；紧急控制在一屏内可达。
